# Cairn best-practices audit

Written 2026-10-10 at commit 9497c05 (story mw-vtjxh4.28). It reads Cairn against the Governor's standing rules and changes nothing: no source file moved, no behaviour changed. The rules live in the factory vault, `seats/builder/pwa-best-practices/` (the quick checklist is `checklist.md`, each rule is argued in the numbered section it points to) and `seats/builder/library-best-practices/01-when-code-becomes-a-library.md` for shared code. The repo's older `docs/pwa-best-practices.md` is a stale copy of an earlier edition and is not the standard (see "Beyond the ten").

## How to read it

- **Status**: `pass`, `fail` or `n/a`. A line with several parts is `fail` when any part fails, and its evidence says which parts pass.
- **Evidence**: a `file:line` in this repo (every one is checked by the loop at the end), a command and what it printed, or why the rule does not apply. A part of the app that is not a PWA would be `n/a` for PWA rows and said so; Cairn is wholly a PWA (React, Vite, Dexie), with no Android app and no server, so the `n/a` rows below are rules about features Cairn does not have.
- **Fix** and **Size** appear on every `fail`. Size: **S** is one sitting (under about 30 changed lines), **M** is one story (up to about 200 lines), **L** is more than one story.
- Cairn was built before most of these rules were written down (first commit 2026-06-13); the gaps are the distance between that build and today's standard, not a recent regression.
- What a unit test cannot show (layout, keyboard, real service worker) was not measured here: no phone and no browser was used. Rows that rest on code reading say so.

## Checking the file:line citations

Every `file:line` above was checked by this loop (run from the repo root; it prints a line for each bad citation and nothing when all are good):

```sh
grep -oE '`[A-Za-z0-9_./-]+\.[A-Za-z0-9]+:[0-9]+(-[0-9]+)?`' docs/best-practices-audit.md | tr -d '`' | sort -u |
while IFS= read -r c; do
  f=${c%%:*}; r=${c#*:}; n=${r%%-*}; m=${r##*-}
  [ -f "$f" ] && [ "$n" -ge 1 ] && [ "$m" -le "$(wc -l < "$f")" ] || echo "BAD $c"
done
```
